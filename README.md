# Python Backend Lab

Three small Python APIs built with Flask, inspired by exercises in [Asabeneh's 30 Days of Python](https://github.com/Asabeneh/30-Days-Of-Python). Each project focuses on one backend skill and runs without cloud accounts, credentials, or paid services.

| Project | What it does | Backend skills | Course inspiration |
| --- | --- | --- | --- |
| Text Analyzer | Counts characters and words; ranks frequent words | JSON validation, Unicode text processing, deterministic sorting | [Day 26: Python for web](https://github.com/Asabeneh/30-Days-Of-Python/blob/master/26_Day_Python_web/26_python_web.md) |
| Student Records | Creates, reads, updates, and deletes persistent records | REST, SQLite, parameterized SQL, pagination | [Day 29: Building API](https://github.com/Asabeneh/30-Days-Of-Python/blob/master/29_Day_Building_API/29_building_API.md) |
| Countries Insights | Filters a JSON dataset and ranks populations and languages | File parsing, validation, filtering, aggregation | [Day 19: File handling](https://github.com/Asabeneh/30-Days-Of-Python/blob/master/19_Day_File_handling/19_file_handling.md) |

The implementations are original adaptations, not copies of the course solutions. Student Records uses SQLite instead of the course's MongoDB; Countries Insights exposes file exercises as API endpoints. The bundled countries and population numbers are **fictional demonstration data**, not real-world statistics.

## Run locally

Use Python 3.11 or newer. These commands assume macOS/Linux; on Windows, activate the environment with `.venv\Scripts\Activate.ps1`.

```bash
git clone https://github.com/SonolaDY/python-backend-lab.git
cd python-backend-lab
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m flask --app backend_lab run --host 127.0.0.1 --port 5050
```

In another terminal, run the three-project demo:

```bash
python3 examples/demo.py
```

The demo creates one fictional student, updates and reads it, then deletes that record. It prints a text analysis result and country statistics. The app creates `instance/lab.sqlite3` automatically; records persist across restarts. That directory is excluded from Git.

## Try the endpoints

### 1. Text Analyzer

```bash
curl -s http://127.0.0.1:5050/api/v1/analyze \
  -H 'Content-Type: application/json' \
  -d '{"text":"Python builds APIs. Python makes data useful.","top_n":3}'
```

Words are Unicode letter sequences, optionally containing internal apostrophes. Matching ignores case and normalizes curly apostrophes. Numbers are excluded; hyphens separate words. Ties sort alphabetically. `character_count` counts Python Unicode code points including spaces and punctuation, not bytes or visual grapheme clusters. Empty text returns zero counts. `text` is required, up to 50,000 characters; `top_n` defaults to 10 and accepts 1–50.

### 2. Student Records

```bash
# Create a fictional record; the response includes its id and Location header.
curl -i http://127.0.0.1:5050/api/v1/students \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ada Example","country":"Demo","skills":["Python","SQL"]}'

# List, filter, and paginate.
curl -s 'http://127.0.0.1:5050/api/v1/students?country=Demo&page=1&per_page=10'

# Replace 1 below with the id returned when creating the record.
curl -s http://127.0.0.1:5050/api/v1/students/1
curl -s -X PATCH http://127.0.0.1:5050/api/v1/students/1 \
  -H 'Content-Type: application/json' -d '{"skills":["Python","SQL","Flask"]}'
curl -i -X DELETE http://127.0.0.1:5050/api/v1/students/1
```

`name` is required and cannot be blank. Optional fields: `country`, `city`, `birth_year`, `skills`, and `bio`. Names, countries, and cities allow up to 120 characters; bio allows 2,000. `birth_year` accepts null or an integer from 1900 through the current UTC year. Skills accepts up to 30 nonempty strings of 80 characters each. Duplicate skill labels are removed. PATCH updates only supplied fields. Unknown fields are rejected.

Lists return `items`, `total`, `page`, and `per_page`. Page size defaults to 20 and is capped at 100. Country filtering is exact with SQLite's ASCII case-insensitive matching. Records sort by id. Creation returns 201, successful deletion 204, and missing records 404. UTC creation/update timestamps are generated by the server.

### 3. Countries Insights

```bash
curl -s 'http://127.0.0.1:5050/api/v1/countries?language=English&sort=population&limit=2'
curl -s 'http://127.0.0.1:5050/api/v1/countries/stats?top_n=3'
```

`name` matches a case-insensitive substring; `language` matches a normalized exact label. Both endpoints support those filters. Listing supports `sort=name` (ascending, default) or `sort=population` (descending) and `limit` from 1–250 (default 20). Statistics supports `top_n` from 1–50 (default 10).

Language rankings count **countries that list each language**, not speakers. Statistics are calculated over all matching records before listing limits. Population ties sort by country name; language ties sort by label.

To use your own dataset, provide a nonempty JSON array with unique `name` values, nonnegative integer `population` values, and nonempty `languages` arrays:

```json
[{"name":"Example Country","population":100000,"languages":["English"]}]
```

```bash
COUNTRIES_FILE=/absolute/path/countries.json python -m flask --app backend_lab run --port 5050
```

The dataset is validated and loaded once at startup. Restart to load changes. Responses identify the dataset as `fictional-demo` or `custom`; document the date and source of any real-world data you supply. Extra dataset fields are ignored.

## Layout

```text
backend_lab/
  __init__.py             Application factory, setup, JSON HTTP errors
  text_analyzer.py       Text processing and POST endpoint
  students.py            SQLite connections and CRUD endpoints
  countries.py           Dataset validation and read endpoints
  validation.py          Shared request validation
  sample_countries.json  Fictional sample dataset
tests/                   API and persistence tests
examples/demo.py         Live HTTP walkthrough using Python's standard library
docs/WALKTHROUGH.md       Code-reading guide and small follow-up exercises
```

All expected HTTP errors return `{"error":{"code":400,"message":"..."}}` with the corresponding status code. Request bodies are limited to 128 KiB. Malformed JSON returns 400; unsupported content types return 415. Unknown or repeated list-query parameters return 400.

## Scope and next steps

This is a local learning portfolio, using synthetic records. It has no login, authorization, migrations, or production deployment configuration. The Flask development server binds to localhost. Before hosting it for real users, add authentication and access checks, a production server, database migrations, and operational monitoring. An optional `DATABASE_PATH` environment variable chooses the SQLite file; its parent directory must already exist.

Tests cover CRUD, restart persistence, rejected inputs without partial updates, SQL-injection-shaped values, pagination, Unicode text, and dataset aggregation. GitHub Actions runs the suite on Python 3.11 and 3.12.

Start with the [walkthrough](docs/WALKTHROUGH.md). The Student Records API is the closest match to CRM work because it handles structured records, validation, and persistent updates. These projects demonstrate Python backend fundamentals; they do not demonstrate Apex, SOQL, LWC, or Salesforce configuration.
